# Техническое задание: Десктопное приложение для управления заявками на закупку инструмента

## 1. Назначение и стек технологий

Разработка высокопроизводительного кроссплатформенного десктопного приложения для создания, редактирования, валидации и экспорта заводских заявок на закупку металлорежущего инструмента и технологической оснастки.

* **Язык бэкенда**: Go (1.21+)
* **Десктопный фреймворк**: Wails v2 (сборка в единый автономный `.exe` без сторонних рантаймов, рендеринг через системный WebView2)
* **Фронтенд**: Svelte (или чистый TS/HTML5/CSS) с поддержкой реактивности, адаптивной flex/grid-верстки и компонентной архитектуры
* **Целевая платформа**: Windows 10/11 x64
* **Совместимость на стороне заказчика**: Обязательная поддержка открытия создаваемых файлов в **Apache OpenOffice Calc** и **LibreOffice Calc** (на рабочих машинах коллег отсутствует пакет Microsoft Office).

## 2. Модель данных и каноничный формат Markdown (`.md`)

Приложение оперирует структурой документа, сериализуемой в открытый текстовый формат Markdown.

### Пример файла `.md`:

```markdown
#52 от 11.06.2026
Подразделение: Цех 3
Пункт: Механосборочный цех № 3
Инициатор: Инженер-программист; Давиденко А.А.
Куратор: Начальник цеха №3; Рыбкин П.В.
Дата поставки: 15.06.2026
Требования: Без дефектов, заводской сертификат качества
Цель: Для изготовления КЭМЗ БК8.035.825

Сверло т/с; EDS08090-0, ExTex D9.0x8D; шт.; 2
Развертка т/с; D9.2H7; шт.; 2
Фреза концевая монолитная; HM60-S4-05130550, ExTex (D5); шт.; 4

```

### Правила парсинга и валидации:

1. **Заголовок**: Первая строка обязана содержать номер и дату в формате `#[номер] от [ДД.ММ.ГГГГ]`.
2. **Даты**: Унифицированный строгий формат `ДД.ММ.ГГГГ` (полный 4-значный год).
3. **Метаданные**: Префиксы `Подразделение:`, `Пункт:`, `Инициатор:`, `Куратор:`, `Дата поставки:`, `Требования:`, `Цель:`.
4. **Подписанты**: Должность и ФИО разделяются символом `;` (без завершающей точки с запятой в конце строки).
5. **Разделитель**: Обязательная пустая строка между блоком метаданных и спецификацией.
6. **Спецификация инструмента**: Позиции перечисляются без маркеров списка (`-`, `*`). Структура строки: `Наименование; Характеристики (типоразмер/марка); Ед. изм.; Количество`.

## 3. Бэкенд-архитектура (Go Core)

### 3.1. Структуры данных

```go
type Document struct {
    ID         string   `json:"id"`
    FilePath   string   `json:"filePath"`
    IsModified bool     `json:"isModified"`
    Meta       MetaInfo `json:"meta"`
    Items      []Item   `json:"items"`
}

type MetaInfo struct {
    BidNum       string `json:"bidNum"`
    BidDate      string `json:"bidDate"`
    Dept         string `json:"dept"`         // "Подразделение" в шапке (напр. Цех 3)
    ShopName     string `json:"shopName"`     // "Пункт" (напр. Механосборочный цех № 3)
    InitRole     string `json:"initRole"`     // Должность инициатора
    InitFio      string `json:"initFio"`      // ФИО инициатора
    CurRole      string `json:"curRole"`      // Должность куратора
    CurFio       string `json:"curFio"`       // ФИО куратора
    DeliveryDate string `json:"deliveryDate"` // Желаемая дата поставки
    QualityReq   string `json:"qualityReq"`   // Требования к качеству
    Purpose      string `json:"purpose"`      // Цель закупки
}

type Item struct {
    Num  int    `json:"num"`
    Name string `json:"name"`
    Desc string `json:"desc"`
    Unit string `json:"unit"`
    Qty  string `json:"qty"`
}

```

### 3.2. Модуль генерации Excel (`.xlsx`)

Реализуется с помощью `[github.com/xuri/excelize/v2](https://github.com/xuri/excelize/v2)` в точном соответствии с заводским шаблоном:

* **Ширины столбцов (символы)**: A: 4.14, B: 29.57, C: 20.85, D: 21.57, E: 8.43, F: 9.29.
* **Высоты строк (pt)**:
* R1: 15.0, R2: 5.25 (разделитель), R3: 15.0, R4: 4.5, R5: 27.0, R6: 35.45, R7: 33.6, R8: 4.5.
* R9: 16.5, R10: 4.5, R11: 32.25, R12: 54.75, R13: 15.0, R14: 33.0, R15: 54.0, R16: 3.0, R17: 16.5, R18: 4.5.
* R19 (шапка таблицы позиций): 36.0.
* R20+ (строки инструментов): 30.0.


* **Объединения ячеек**:
* `C1:F1` — подчеркивание номера заявки (нижняя граница thin).
* `D3:F3` — блок подразделения (контурная рамка medium).
* `A6:B6`, `A7:B7` — ячейки «ИНИЦИАТОР ЗАКУПКИ» и «КУРАТОР ЗАКУПКИ».
* `A9:F9` — «I. Общие сведения».
* `B11:C11`, `D11:F11` — шапка раздела I.
* `B12:C12` ... `B15:C15` и `D12:F12` ... `D15:F15` — пункты раздела I.
* `A17:F17` — «II. Техническая часть документации».
* `C19:D19` — колонка «Характеристики товара» в шапке и на каждой строке позиций.


* **Параметры печати**: Альбомная/книжная ориентация: Portrait, `FitToWidth: 1`, сквозной повтор заголовка таблицы на каждой странице через `SetSheetPrOptions` (`PrintTitles` = `19:19`).

### 3.3. Модуль генерации OpenDocument Spreadsheet (`.ods`)

Реализуется автономно через стандартные пакеты Go `archive/zip` и `encoding/xml` без сторонних CGo-библиотек:

* Формирование архива со структурой: `mimetype` (uncompressed, `application/vnd.oasis.opendocument.spreadsheet`), `META-INF/manifest.xml`, `styles.xml`, `content.xml`.
* **Стили и разметка**:
* Фиксация ширин колонок в сантиметрах: A: 1.0cm, B: 6.0cm, C: 4.3cm, D: 4.3cm, E: 1.7cm, F: 1.9cm.
* Границы ячеек таблицы: `fo:border="0.5pt solid #000000"`, отступы ячеек `fo:padding="2pt"`, шрифт Calibri/Liberation Sans 11pt.
* Рамка блока подразделения: `fo:border="1.2pt solid #000000"`.
* Линия под номером заявки: `fo:border-bottom="0.8pt solid #000000"`.



### 3.4. Модуль генерации и предпросмотра PDF

* Подготовка адаптивного HTML/CSS шаблона печатного листа A4 с отступами 10 мм.
* Использование нативного рендерера Wails WebView2 (функция печати в PDF / превью через canvas/SVG или `PDF.js`).
* Шапка: расстояние между номером заявки и подразделением для исключения наложения линии подчеркивания на рамку цеха.
* Автоматический перенос шапки таблицы позиций на вторую и последующие страницы (`thead { display: table-header-group; }`).

## 4. Архитектура пользовательского интерфейса (Frontend)

### 4.1. Макет и компоновка

Интерфейс разделен на три функциональные зоны:

```
+----+--------------------------------+--------------------------------+
|    | Меню: [Файл v] [◀ Вкладки]      | Режимы: [⚖ Сплит] [📝 Ввод]    |
|    | [⚙ Настройки]                  |         [🔍 Предпросмотр]      |
|    +--------------------------------+--------------------------------+
| В  | Форма метаданных (Flex/Grid):                                   |
| К  |  Заявка № [52] от [11.06.2026 📅]   Подразделение [Цех 3]      |
| Л  |  Пункт [Механосборочный...]         Поставка [15.06.2026 📅]    |
| А  |  Инициатор [Должность 50%]          [ФИО 50%]                   |
| Д  |  Куратор   [Должность 50%]          [ФИО 50%]                   |
| К  |  Цель [Для изготовления...]                                     |
| И  |  Требования [Без дефектов...] (на всю ширину)                  |
|    +--------------------------------+--------------------------------+
|    | Редактор инструмента:          | Интерактивный предпросмотр:    |
|    | 1 | Сверло т/с; D9.0; шт.; 2   |     +--------------------+     |
|    | 2 | Развертка т/с; D9.2; шт; 2 |     |    Лист A4 PDF     |     |
|    |   |                            |     | (центрирован по W) |     |
|    |   | (word-wrap, без гор.скролла|     +--------------------+     |
|    |   |  gutter-номера, vs-скролл) |  [🔍-] [100%] [🔍+] [1:1]     |
|    |   |                            |  [◀] Стр. 1 из 2 [▶]           |
+----+--------------------------------+--------------------------------+

```

### 4.2. Боковая панель вкладок (Arc / Chrome style)

* Расположена у левого края окна.
* Сворачивается и разворачивается по клику на кнопку в шапке (`◀ Вкладки` / `▶ Вкладки`).
* **Название вкладки**: содержит только номер заявки (максимум 5 символов, при превышении обрезается с многоточием: `52`, `12345...`).
* **Индикатор изменений**: при наличии несохраненных данных возле имени вкладки выводится белый кружок (`○`), который гаснет после успешного сохранения на диск.
* Кнопка `+` создает новую пустую вкладку. Кнопка `×` закрывает вкладку с вызовом диалога подтверждения, если данные были модифицированы.

### 4.3. Адаптивная форма параметров заявки (Flex/Grid)

* Минимальная высота по вертикали.
* Плавное сжатие колонок без визуального наложения элементов при изменении размеров сплиттера:
* Поля «Должность» и «ФИО» (инициатор и куратор) делят доступную ширину строго поровну ($50\% / 50\%$).
* Поле «Пункт» имеет компактную базовую ширину.
* Поле «Требования» располагается в самом низу формы отдельной строкой и занимает $100\%$ доступной ширины.
* Поля дат снабжены всплывающим интерактивным календарем с быстрым выбором сегодняшней даты и кнопкой очистки.



### 4.4. Редактор спецификации позиций инструмента

* **Gutter (полоса нумерации)**: вертикальный столбец слева от текста, автоматически нумерует строки `1, 2, 3...`. Номера не попадают в буфер обмена при копировании.
* **Подсветка строки**: мягкое фоновое выделение строки, на которой установлен текстовый курсор.
* **Перенос строк**: включен `word-wrap`, исключающий появление горизонтального скроллбара.
* **Скроллбары**: тонкие стилизованные полосы прокрутки в эстетике VS Code.

### 4.5. Панель предпросмотра

* Автоматическое горизонтальное центрирование страницы формата А4 при любой ширине окна.
* Масштабирование (Zoom): кнопки `🔍 −`, `100%`, `🔍 +`, `1:1`, а также поддержка `Ctrl + Колесо мыши`.
* Навигация по страницам: кнопки перелистывания `◀`, индикатор текущей страницы, `▶`.
* **Режимы отображения окна**:
* `⚖ Разделить экран` — двухпанельный вид (форма + редактор слева, превью справа).
* `📝 Только ввод` — скрывает предпросмотр, отдавая $100\%$ ширины редактору.
* `🔍 Предпросмотр на всё окно` — скрывает форму и редактор, разворачивая превью на $100\%$ ширины.

## 5. Горячие клавиши и UX-протокол

* **`Ctrl + S`**: Быстрое сохранение активной вкладки. Если файл уже открыт с диска, сохранение выполняется без показа диалоговых окон, а индикатор `○` мгновенно гаснет. Если вкладка новая — вызывается системный диалог «Сохранить как...».
* **`F5`**: Перезагрузка текущего файла с диска (по логике Notepad++):
* Если изменений в редакторе не было — файл тихо перечитывается.
* Если во вкладке есть несохраненные данные — появляется модальное предупреждение: *«Файл был изменен в редакторе. Перезагрузить файл с диска и потерять несохраненные изменения?»*.


* **`Ctrl + Z` / `Ctrl + Y` / `Ctrl + Shift+ Z**`: Полноценный Undo/Redo со схлопыванием пословной истории при нажатии пробела и Enter.
* **Универсальность раскладок**: Перехват сочетаний клавиш привязан к физическим скан-кодам (keycode), что обеспечивает бесперебойную работу копирования, вставки и отмены как в русской, так и в английской раскладке клавиатуры.

## 6. Темы оформления (Catppuccin) и типографика

Приложение поддерживает четыре официальные темы палитры **Catppuccin**:

1. **Catppuccin Mocha** (темная тема по умолчанию):
* Base: `#1e1e2e`, Mantle: `#181825`, Crust: `#11111b`, Text: `#cdd6f4`, Surface0: `#313244`, Accent: `#89b4fa`.


2. **Catppuccin Macchiato** (темная)
3. **Catppuccin Frappé** (темная)
4. **Catppuccin Latte** (светлая):
* Base: `#eff1f5`, Mantle: `#e6e9ef`, Text: `#4c4f69`, Surface0: `#ccd0da`, Accent: `#1e66f5`.



В темных темах элементы формы, метки, фон редактора, скроллбары и панели окрашиваются строго в цвета палитры, исключая появление белых пятен и рамок.

### Шрифтовая иерархия:

* Элементы интерфейса, кнопки, меню: **11 pt**.
* Поля формы ввода и метки: **12 pt**.
* Текстовый редактор спецификации: **12 pt**, шрифт по умолчанию — **`Cascadia Code`** (с автоматическим системным фолбеком на **`Consolas`**).
* Окно настроек (`⚙ Настройки`): список шрифтов редактора формируется динамически и содержит **только реально установленные в операционной системе шрифты**.

## 7. Консольный конвертер (`excel_to_md.py`)

Вспомогательный скрипт на Python для пакетного импорта входящих заявок из Excel в Markdown:

* Поддержка запуска методом Drag-and-Drop на `.bat` файл.
* Корректная обработка объединенных ячеек таблицы Excel (`merged_cells`).
* Автоматическая нормализация входящих дат любых форматов (`datetime`, `date`, `DD.MM.YY`, `MM/DD/YYYY`) в каноничный вид `ДД.ММ.ГГГГ`.
* Очистка должностей и ФИО от концевых точек с запятой.
* Добавление пустой строки-разделителя перед списком спецификации.

## 8. Архитектурные требования к автономности сборки

1. Проект Wails компилируется флагом `-windowsconsole=false` в единый бинарный файл `tool-bid-app.exe`.
2. Никаких внешних DLL, зависимостей от локально установленного Python, TeX-дистрибутивов или пакета Microsoft Office.
3. Сохранение высокой отзывчивости UI за счет разделения потоков: тяжелые операции экспорта и валидации выполняются в горутинах бэкенда, не блокируя событийный цикл интерфейса.
